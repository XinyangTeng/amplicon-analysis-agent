# Architecture

The system deliberately separates biological judgment, deterministic execution, and language-model assistance. The model may explain input problems before a plan exists, but it never performs numerical analysis and cannot bypass approval.

The public Web surface adds an outer multi-user boundary without changing the
scientific execution layers:

```text
Public landing page
        |
Invitation-only account + CSRF-protected session
        |
Per-user workspace and resource ownership checks
        |
User-selected group column + deterministic inspection
        |
Optional right-side AI assistant
  - compact metadata summary, never the abundance matrix
  - proposed edits become a preview, never an in-place mutation
  - explicit user confirmation before a corrected copy is activated
        |
Redis + Celery queue
  - per-user concurrency
  - wall-time, CPU and memory limits
  - cancellation and expiry cleanup
        |
The same AgentService, R functions, validator and report builder
```

Account metadata, sessions, quotas, resource ownership and task state are stored
in a small global SQLite database. Uploaded research data and generated results
are never placed in that database; they remain under
`workspace/users/<user-id>/`. The MCP-only local workflow continues to use the
workspace root directly.

```text
User and project files
        |
        v
LLM + expert Skill
  - parse the biological question and experiment design
  - organize required inputs
  - select eligible analyses and explain limitations
        |
        v
MCP Server
  - validate tool schemas and workspace paths
  - inspect inputs and create an immutable Analysis Contract
  - enforce file hashes and one-time approval
  - orchestrate execution, validation, status, and audit records
        |
        v
Deterministic executors
  - baseline R analysis
  - registered R functions in batch-isolated workspaces
        |
        v
Deterministic validation and report builder
  - validate statistical and file invariants
  - recursively scan all output files
  - embed PNG figures only and keep PDFs as downloads
  - write report.html, report_data.json, and artifact_manifest.json
        |
        v
LLM interpretation
  - read compact validated context through get_report_context
  - fetch only selected evidence tables through get_result_table
  - separate facts, statistics, interpretation, and hypotheses
  - write interpretation.json through save_analysis_interpretation
        |
        v
Fixed report rebuild
  - merge the validated project-specific interpretation into report.html
```

## Why the report is not generated by the LLM

File discovery, image placement, result indexing, and execution-state checks are deterministic tasks. The report builder therefore scans the run directory after all requested functions finish. A newly added function can contribute PNG figures, result tables, PDFs, and logs without changing the HTML template. Only PNG files are embedded, preventing duplicate display of PDF/PNG copies.

`report_data.json` is the full machine-readable record. The default MCP context omits the full artifact inventory and returns a compact result-table index. The model reads only the few CSV/TSV tables required to support its claims.

The HTML structure and file placement remain deterministic. Biological interpretation is a separate validated `interpretation.json`, produced only after successful validation and merged by the same fixed report builder. It can be revised without rerunning the numerical analysis.
